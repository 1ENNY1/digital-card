# Digital card

Бэкенд-визитка: GraphQL API с информацией обо мне, навыками, опытом и проектами.
Стек: TypeScript, NestJS, Prisma, PostgreSQL, GraphQL (Apollo), Docker.

## Запуск

```bash
docker compose up --build
```

После старта Apollo Sandbox доступен на http://localhost:3000/graphql.
Миграции и заполнение базы выполняются автоматически при запуске контейнера.

Без Docker: нужен запущенный PostgreSQL, `.env` по образцу `.env.example`, дальше

```bash
npm install
npm run db:init
npm run start:dev
```

Данные визитки лежат в `prisma/seed-data.ts`.

Пример запроса:

```graphql
query {
  profile {
    name
    description
    github
    linkedin
    skills { name }
    experience { company position startDate endDate achievements }
    projects { name url }
  }
}
```

## Как устроено и почему

**Слои.** Резолвер только принимает GraphQL-запрос и вызывает сервис или загрузчики. Сервис получает профиль. Prisma вынесен в отдельный модуль. Я не хотел, чтобы в резолвере появлялись запросы к базе: так проще поддерживать и менять код.

**Code-first.** Типы GraphQL описаны классами с декораторами, схема генерируется из них. Не нужно вести отдельно SDL и TypeScript-типы, меньше шансов, что они разойдутся.

**Вложенные данные.** Навыки, опыт и проекты подгружаются через `@ResolveField` и DataLoader. Загрузчики создаются на каждый запрос, и на каждую связь уходит один запрос `WHERE profileId IN (...)`. Если клиент не запрашивает `projects`, в таблицу проектов мы не ходим. С `include` в запросе профиля так не получилось бы, он тянул бы всё сразу.

**База.** Четыре таблицы: Profile, Skill, Experience, Project. Внешние ключи с каскадным удалением, индексы по `profileId`. Достижения хранятся массивом строк в самой записи об опыте: отдельно они не нужны, и отдельная таблица тут была бы лишней. Период работы это `startDate` и необязательный `endDate`, пустой означает «по настоящее время».

**Миграции и сид.** Схема накатывается через `prisma migrate deploy`. Сид пересоздаёт профиль в одной транзакции, поэтому повторный запуск ничего не дублирует.

**Docker.** Двухэтапная сборка, чтобы в итоговом образе не было лишнего. У Postgres в compose есть healthcheck, приложение стартует только когда база готова.

**Sandbox.** Подключён через плагин Apollo Server на странице `/graphql`. Introspection включён, потому что API публичное и только для чтения.

Чего нет: аутентификации, мутаций и автотестов. Для визитки это показалось лишним, но тесты на запрос `profile` я бы добавил следующим шагом.

## Деплой (Render)

Репозиторий на GitHub, затем в Render: New → Blueprint, выбрать репозиторий (настройки в `render.yaml`).
Сервис будет доступен по адресу `https://<имя>.onrender.com/graphql`. На бесплатном тарифе после простоя первый запрос может идти около минуты.
